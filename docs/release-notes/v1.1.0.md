# libazahar-py v1.1.0

A headless, scriptable host for Azahar's 3DS libretro core, with a Python layer, for testing homebrew. This release
adds Windows x64. macOS is unchanged: it needs macOS 15 or later on Apple silicon, and it uses the same core as
v1.0.0. The 1.0 promise (semantic versioning: until 2.0, the Python API, the C functions in `host/azhost.h`, the
`azhost` command line and exit codes, and the input-script and option-profile formats change only in compatible ways)
holds on both systems. `STATUS.md` in the repository says what works and what does not.

this project is not affiliated with Nintendo.

## What is new

- A native Windows x64 build: our core (`azahar_lazpy_libretro.dll`), the host library (`libazhost.dll`), the
  `azhost.exe` command and the Python layer, with no WSL.
- You build the host yourself in the MSYS2 MINGW64 shell, with `make`; the README has the steps. The core comes from
  this release through `tools/fetch.sh`.
- `tools/fetch.sh` falls back to the v1.0.0 page for the macOS core and the test app if this page cannot be reached.
- Version 1.1.0 in `pyproject.toml` and `libazahar.__version__`.
- The host also accepts the stock core when it names itself `219d743`, the pinned commit: Azahar's official Windows
  build of 2126.2 reports that instead of `2126.2`.

## Windows differences

- Files are `libazhost.dll`, `azhost.exe` and `azahar_lazpy_libretro.dll`.
- `LAZ_MVK` names the Vulkan loader. The default is `vulkan-1.dll` from System32. A GPU driver with Vulkan is
  required; no Vulkan is shipped.
- `LoadWarning` is never raised. The worker runs at BELOW_NORMAL priority instead of a nice value.
- Slots live in `%LOCALAPPDATA%\libazahar-py\slots`, and `Slot.fd` is a HANDLE.
- Paths must be ASCII and under 260 characters: clone into a short path such as `C:\src`.
- The SD folder is case-insensitive. `runs/` behind a junction is not supported.
- There is no lazpy.1 Windows core; the Windows core is lazpy.2.
- On Windows the guest's HTTPS finds no CA file: the compiled-in OPENSSLDIR is `/opt/lazpy/openssl-3.6.5-mingw64/C:/Program Files/Common Files/SSL`, not a usable Windows path
  (OpenSSL's cross build joined its install prefix to the Windows path).
- Savestates do not carry between macOS and Windows: a state from the other system is refused with `StateError`,
  "incompatible native format - size of long" (`long` is 8 bytes on macOS, 4 on Windows). The 1.0.0 state fixture,
  made on macOS, is refused this way on Windows; the fixture test checks that refusal there.

`docs/USING.md` section 15a has the table.

## Limits

- Proven on one PC only: Windows 10 Pro 22H2, x64, an NVIDIA GeForce RTX 3060, driver 610.88, Python 3.10.11.
- CI adds Windows Server 2025 for the build, the fast tests and the core load test.
- Windows 11 and AMD and Intel GPUs are untested.
- No Windows speed figures. The instance cap stays 4.
- macOS needs macOS 15 or later on Apple silicon.

## Assets

Inherited from v1.0.0, the same bytes (the macOS core and its source):
- `azahar_lazpy_libretro-2126.2-lazpy.2-macos-arm64.zip`: our macOS core.
- `libazahar-py-core-build-v1.0.0.tar.gz`: the patches, pins, options and build script for the macOS core.
- `azahar-unified-source-2126.2-lazpy-nokeys.tar.xz`: the Azahar source both cores were built from.
- `openssl-3.6.5.tar.gz`: OpenSSL's source tarball.
- `citra_system_archives-f470e0c.tar.gz`: the generator snapshot behind the system archives in the core.
- `testapp.3dsx`: the small homebrew test app used by the tests.
- `NOTICES.md`: the macOS licence notices.

New in v1.1.0:
- `azahar_lazpy_libretro-2126.2-lazpy.2-windows-x64.zip`: our Windows core, with `NOTICES.md`, `SOURCE.md`, `LICENSE`,
  `COPYING-azahar.txt` and `build.inputs`.
- `NOTICES-windows-x64.md`: the Windows zip's notices, also as a plain file.
- `libazahar-py-core-build-v1.1.0.tar.gz`: the build files for the Windows core.
- `mingw-w64-runtime-source.tar`: the source of the compiler runtime parts linked into the Windows core.
- `SOURCE.md`: maps each binary to its source.
- `SHA256SUMS`: sha256 of every other asset.

## Licence and source

Both core binaries are GPLv3. Their complete corresponding source is on this page: the Azahar source asset, the OpenSSL
source tarball, the system-archive generator snapshot, both build-files assets, the compiler runtime source, and this
repository at the tag. The Windows core links OpenSSL (Apache-2.0) statically; its runtime parts keep their own
licences, listed in `NOTICES-windows-x64.md`.

## Homebrew only

Homebrew only: no ROMs, no console keys, no Nintendo certificates and no Nintendo system files are included or needed by the tests; our core is built
without Azahar's built-in key data and default HTTP client certificate, and it loads no keys.

## Install

See the README, which has macOS and Windows steps. On macOS, macOS 15 or later is required.
